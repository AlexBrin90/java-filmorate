### Таблица `users`

Хранит пользователей сервиса.

- **Первичный ключ:** `id`
- **Уникальные поля:** `email`, `login`
- **Обязательные поля:** `email`, `login`
- **Дополнительные поля:** `name`, `birthday`

Сюда ссылаются таблицы `likes` и `friendships`, потому что лайки и дружба всегда привязаны к конкретному пользователю.


### Таблица `friendships`

Хранит информацию о дружбе между пользователями.

- **Первичный ключ:** составной ключ из полей `user_id` и `friend_id`
- **Поля:**
  - `user_id` — пользователь, от которого исходит отношение дружбы;
  - `friend_id` — пользователь, с которым дружат;
  - `status` — статус дружбы, например: заявка, подтверждена, отклонена.

Одна и та же пара пользователей не может быть записана дважды, так как `user_id + friend_id` являются первичным ключом.

Внешние ключи:

- `friendships.user_id` ссылается на `users.id`
- `friendships.friend_id` ссылается на `users.id`

Индекс по полю `friend_id` нужен для быстрого поиска пользователей, которые являются чьими-то друзьями.


### Таблица `films`

Хранит информацию о фильмах.

- **Первичный ключ:** `id`
- **Обязательные поля:** `name`, `description`
- **Дополнительные поля:**
  - `release_date` — дата выхода фильма;
  - `duration` — длительность фильма;
  - `mpa_rating_id` — ссылка на возрастной рейтинг.

Внешний ключ:

- `films.mpa_rating_id` ссылается на `mpa_ratings.id`

То есть у каждого фильма может быть один возрастной рейтинг, но один и тот же рейтинг может использоваться у многих фильмов.


### Таблица `mpa_ratings`

Справочник возрастных рейтингов.

- **Первичный ключ:** `id`
- **Уникальное обязательное поле:** `name`
- **Дополнительное поле:** `description`

На эту таблицу ссылается `films.mpa_rating_id`.


### Таблица `genres`

Справочник жанров фильмов.

- **Первичный ключ:** `id`
- **Уникальное обязательное поле:** `name`
- **Дополнительное поле:** `description`

На эту таблицу ссылается таблица `film_genres`.


### Таблица `film_genres`

Связывает фильмы и жанры. Нужна для связи «многие ко многим»: один фильм может иметь несколько жанров, а один жанр может относиться ко многим фильмам.

- **Первичный ключ:** составной ключ из полей `film_id` и `genre_id`

Внешние ключи:

- `film_genres.film_id` ссылается на `films.id`
- `film_genres.genre_id` ссылается на `genres.id`

Один и тот же жанр нельзя привязать к одному и тому же фильму дважды.


### Таблица `likes`

Хранит информацию о лайках пользователей.

- **Первичный ключ:** составной ключ из полей `user_id` и `film_id`
- **Поля:**
  - `user_id` — пользователь, который поставил лайк;
  - `film_id` — фильм, который лайкнули.

Внешние ключи:

- `likes.user_id` ссылается на `users.id`
- `likes.film_id` ссылается на `films.id`

Один пользователь может поставить только один лайк одному фильму.

Индекс по полю `film_id` помогает быстро находить все лайки конкретного фильма.


### Общие связи схемы

- Пользователь может поставить много лайков.
- Фильм может получить много лайков от разных пользователей.
- Пользователи могут дружить между собой через таблицу `friendships`.
- Фильм может иметь несколько жанров через таблицу `film_genres`.
- Жанр может относиться ко многим фильмам через таблицу `film_genres`.
